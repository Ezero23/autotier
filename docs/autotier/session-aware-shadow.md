# Session-aware Shadow 设计说明

## 目的

AutoTier 的 v0.1 仍然是 Shadow-only：它只记录特征、候选和决策解释，不执行模型切换。此次优化把从上游代理项目学到的两条原则落到 Shadow 链路：

1. **会话连续性**：同一会话的复杂度趋势和上一轮候选不应每次请求都从空状态开始；
2. **有界状态**：会话状态必须有容量上限和最近使用淘汰，不能因为长期运行的代理而无限增长。

## 实现边界

- 会话 key 是 `(app_type, HMAC(session_id))`。原始 Session ID 只在请求处理的内存路径中短暂使用，不进入数据库或导出文件。
- `RoutingSessionStore` 只保存 `RoutingSessionState`，容量默认 2000 个会话；代理重启时状态清空。
- 状态更新在一次内存锁操作中完成，避免并发请求对同一会话发生读改写丢失。回调不允许做数据库、网络或异步操作。
- LRU 淘汰是安全降级：被淘汰的会话下一次从默认状态开始，不影响真实请求。

## 缓存保护策略

当请求特征表明存在 cache read/write token，且上一轮候选等级高于本轮基础推荐时，Shadow 候选保持上一轮较高槽位，避免在会话内无依据降档并破坏缓存/上下文连续性。

以下优先级不变：

- 客户端显式请求小模型优先于缓存保护；
- 复杂度上升可以跨过缓存保护升档；
- `safe_to_execute` 始终为 `false`。

该策略只改变 `recommended_slot` 和解释，不改变请求 body、Provider Router、Forwarder 或真实出站模型/Provider。

## 与上游学习点的对应

上游项目已经在代理层使用有界的会话/Shadow 状态，并对会话连续性、缓存与模型选择做保护。AutoTier 没有直接合并上游 Stack mode，因为那会同时引入真实代理路由、客户端模型目录和大量 Codex/Claude 兼容性变化；本次只提取可独立验证、不会越过 Shadow 安全边界的部分。

## 版本与回放

会话状态开始参与候选策略后，策略版本升为 `shadow-policy-v0.3`。历史决策仍保留各自的版本戳；导入/回放遇到策略版本不匹配时应继续按现有安全规则拒绝，而不是静默用新规则重算。
