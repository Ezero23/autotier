> Shadow 路由观测台 —— 任务控制台与失败即关闭的发布管线

**[English →](v0.1.6-en.md)**

---

## 概览

AutoTier v0.1.6 将原先的代理设置页替换为面向任务的三层控制台，并收紧了正式发布管线。用户可以在「概览」了解当前状态，在「Shadow 结果」复核候选决策，并通过「接入与高级」完成 Agent 接入。

**发布日期**：以 GitHub Release 发布时间为准

**范围**：仅 Shadow 观测。不改变出站模型、Provider 与用户请求。

---

## 亮点

- **概览面板**：展示本地代理状态、Agent 接入情况、真实 Shadow 决策、候选完整性、候选分布、已完成与已复核数量，以及唯一推荐的下一步。
- **Shadow 结果中心**：保留决策列表、Cheap/Mid/Strong 建议、筛选、人工标注、Replay、Eval、导出与建议解释。
- **三步接入流程**：启动本地代理，配置 Agent 使用 AutoTier 端点，然后发送真实任务并观察 Shadow 决策。
- **高级设置收拢**：路由、故障转移、整流器与全局代理默认折叠，降低首次使用负担。
- **失败即关闭的发布**：正式发布现在强制要求 Tauri 更新器签名密钥；签名不可用时构建直接失败，而不是发布空的 `latest.json`。
- **清单校验**：`latest.json` 上传前经过校验，必须包含 macOS、Windows x64/ARM64 与 Linux x64/ARM64 的已签名条目。

---

## 更新器签名密钥轮换

此前的更新器私钥已不可恢复，因此 v0.1.6 内置了**轮换后的公钥**，仓库 Secret 现保存与之匹配的私钥。影响：

- 每个平台重新附带 `.sig` 更新器产物，`latest.json.platforms` 恢复填充——v0.1.5 的空 platforms 回归就此消除。
- **v0.1.5 及更早版本的应用内置旧公钥，无法校验 v0.1.6 的签名。** 请最后一次手动更新：从 [Releases](https://github.com/Ezero23/autotier/releases) 下载安装包覆盖安装；从 v0.1.6 起，应用内自动更新恢复正常。
- 发布工作流现在始终导出签名密码环境变量（空值兜底），签名不再在无终端的 Runner 上回退到交互提示——这正是第一次 v0.1.6 尝试中断的原因。

## 从 v0.1.5 升级

1. 从 [Releases](https://github.com/Ezero23/autotier/releases) 安装 v0.1.6。
2. 在「概览」确认本地代理、Agent 接入与候选配置状态。
3. 完成「接入与高级」下的三步流程；高级控件仅在需要时展开。
4. 继续在「Shadow 结果」中收集并复核真实任务样本。
