## Overview

AutoTier v0.1.6 replaces the former proxy settings page with a task-oriented three-layer console and tightens the formal release pipeline. Users can understand current status from Overview, review candidate decisions in Shadow Results, and connect an Agent through the Connection & Advanced flow.

**Release date**: Set when the GitHub Release is published

**Scope**: Shadow observation only. Outbound models, providers, and user requests are not changed.

---

## Highlights

- **Overview panel**: Shows local proxy status, Agent connection, real Shadow decisions, candidate completeness, candidate distribution, completed and reviewed counts, and one recommended next step.
- **Shadow Results center**: Preserves decision lists, Cheap/Mid/Strong recommendations, filtering, human labels, Replay, Eval, export, and recommendation explanations.
- **Three-step connection flow**: Start the local proxy, configure the Agent to use the AutoTier endpoint, then send real tasks and observe Shadow decisions.
- **Advanced settings are contained**: Routing, Failover, rectifier, and global proxy controls are collapsed by default to reduce first-use overload.
- **Fail-closed releases**: A formal release now requires the Tauri updater signing key; builds fail when signing is unavailable instead of publishing an empty `latest.json`.
- **Manifest validation**: `latest.json` is validated before upload and must contain signed entries for macOS, Windows x64/ARM64, and Linux x64/ARM64.
- **Updater key handling**: CI writes the minisign secret to a file and passes that path to Tauri. It no longer re-encodes the file as base64 (that produced `incorrect updater private key password`). Apple notarization stays optional and does not block updater-signed builds.

---

## Updater signing key rotation

The previous updater private key became unrecoverable, so v0.1.6 embeds a **rotated public key** and the repository secret now holds the matching private key. Consequences:

- Every platform ships `.sig` updater artifacts again, and `latest.json.platforms` is populated — the empty-platforms regression from v0.1.5 is gone.
- **Apps on v0.1.5 or earlier embed the old public key and cannot validate v0.1.6 signatures.** Update manually one last time by downloading the installer from [Releases](https://github.com/Ezero23/autotier/releases); from v0.1.6 onwards, in-app auto-update works normally.
- The release workflow now always exports the signing password environment (empty fallback) so signing never falls back to an interactive prompt on headless runners — the failure that aborted the first v0.1.6 attempt.

## Upgrading from v0.1.5

1. Install v0.1.6 from [Releases](https://github.com/Ezero23/autotier/releases).
2. Use Overview to confirm local proxy, Agent connection, and candidate configuration status.
3. Complete the three-step flow under Connection & Advanced; expand advanced controls only when needed.
4. Continue collecting and reviewing real task samples in Shadow Results.
